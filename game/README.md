# 컬러 스위퍼 스도쿠 (스캐폴딩)

지뢰찾기 뼈대 + 컬러스위퍼식 인접 힌트 + 스도쿠식 행/열 마진 힌트를 결합한
미니게임의 초기 골격입니다. 빌드 도구 없이 `index.html`을 브라우저로 열면
바로 실행됩니다.

세 난이도(쉬움/중급/고급) 모두 완전히 같은 하나의 규칙을 쓰고, 난이도는
격자 크기·색 수·힌트 밀도·기회 네 상수로만 조절합니다. (초기 설계에는
고급 전용 RGB 채널/합성색 개념이 있었지만, 규칙이 너무 복잡해진다고
판단해 걷어내고 이 버전으로 단순화했습니다.)

## 파일 구조

```
index.html              진입 화면 (난이도 선택, 게임판, 팔레트, 설정)
style.css               스타일 (반응형 2단 대응, 이펙트 애니메이션 포함)
js/
  difficulty-config.js  난이도별 상수 — 카드3 튜닝 시 이 파일만 수정
  state.js               중앙 게임 상태 + 포커스 이탈/일시정지 대응
  clue-engine.js          인접 8칸 색 힌트 + 행/열 마진 힌트 계산
  board-generator.js      정답 보드 생성 + 힌트 공개 마스크
  game.js                  칸 선택, 색 배치, 기회 차감, 승패 판정
  effects.js                클리어/실패/경고 이펙트 + 음소거·움직임감소 분기
  storage.js                 최단 클리어 시간 저장/불러오기 + 손상 방어
  ui-render.js               화면 렌더링
  main.js                     진입점, 이벤트 바인딩
```

## 규칙

| 난이도 | 격자 | 색 수 | 힌트 밀도 | 기회 |
|---|---|---|---|---|
| 쉬움 | 6×6 | 3 | 0.55 | 5 |
| 중급 | 9×9 | 3 | 0.45 | 4 |
| 고급 | 10×10 | 2 | 0.35 | 3 |

- 칸 안 숫자: 인접 8칸 중 그 칸과 같은 색의 개수 (지뢰찾기식)
- 가장자리 숫자: 해당 행/열에 각 색이 총 몇 칸 있는지 (스도쿠식 마진 힌트)
- 틀린 색을 놓으면 기회가 하나 줄고, 기회가 0이 되면 실패
- 모든 빈 칸을 올바른 색으로 채우면 클리어

## 아직 완성되지 않은 부분

1. **보드 생성의 유일해 검증 (`board-generator.js`)**
   `isConsistentGuess`가 아직 정답 색만 후보로 인정하는 자리표시자입니다.
   실제로 "찍기 없이 논리로만 풀리는" 보드를 만들려면, 공개된 힌트·마진
   합계를 실제로 대조해서 후보 색을 좁혀나가는 제약전파 로직으로
   교체해야 합니다. 이 프로젝트에서 가장 중요한 남은 작업입니다.
2. **효과음 연결 (`effects.js`)** — `playSound()`가 지금은 콘솔 로그만 남깁니다.
3. **카드2 숨은 검사 대응 점검** — 연속 입력, 창 크기 변경, 포커스 이탈·복귀,
   일시정지·재개, 10분 실행을 직접 돌려보며 안정성을 확인하세요.
4. **카드3 튜닝 기록** — `difficulty-config.js`의 값 하나(예: `chances`)를
   바꿔서 전/후 각 10회 플레이 기록을 비교하고 최종값을 정하세요.
5. **접근성 재확인** — 음소거·움직임 줄이기 토글을 켠 채로 클리어/실패를
   재현해서 효과가 실제로 줄거나 멈추는지 확인하세요.
